Respuestas Por Ejercicio

1. Analisis de planes de ejecucion

Pregunta 1. Antes de crear el indice sobre Empleado_ID, la operacion esperada es Clustered Index Scan sobre la PK de TransaccionNomina, porque la tabla solo tiene el indice clustered del identificador.

Pregunta 2. Antes de optimizar: Scan. Despues de crear el indice no agrupado: Index Seek, con posible Key Lookup por usar SELECT *.

Pregunta 3. Si la consulta se ejecuta sola, SSMS suele mostrar 100% del lote como costo relativo, pero el punto importante es que el costo estimado baja despues del indice y se reduce la lectura innecesaria de paginas.

2. Indices y optimizacion del rendimiento

Pregunta 1. El plan cambia de Clustered Index Scan a NonClustered Index Seek.

Pregunta 2. Si, mejora el rendimiento porque el motor deja de revisar toda la estructura clustered para ir directo a las filas del empleado filtrado.

3. Estadisticas en SQL Server

Las estadisticas son importantes porque permiten al optimizador estimar cuantas filas devolvera una condicion, elegir mejor entre Seek o Scan, y decidir planes mas eficientes para filtros, joins y agregaciones.

4. Concepto ACID y manejo de transacciones

Pregunta 1. Si ocurre un error antes del COMMIT y se ejecuta ROLLBACK, ningun cambio queda persistido.

Pregunta 2. La propiedad ACID que garantiza permanencia es Durability.

5. Uso de ROLLBACK y SAVEPOINT

Pregunta 1. Permanecen los registros insertados antes del SAVEPOINT. La actualizacion posterior es la que se revierte.

Pregunta 2. La ventaja del SAVEPOINT es permitir un rollback parcial sin perder toda la transaccion.

6. Concurrencia y bloqueos

Pregunta 1. La segunda sesion queda esperando el recurso o se bloquea hasta que la primera confirme o revierta.

Pregunta 2. Se produce porque la primera transaccion mantiene un bloqueo exclusivo sobre la misma fila.

7. Niveles de aislamiento

Pregunta 1. READ COMMITTED evita las lecturas sucias.

Pregunta 2. Una dirty read ocurre cuando una transaccion lee datos todavia no confirmados por otra transaccion, y esos datos luego pueden revertirse.

8. Stored Procedures

Pregunta 1. Ventajas: reutilizacion, seguridad, mantenimiento centralizado, menor duplicidad de codigo y mejor control de la logica del negocio.

Pregunta 2. Se ejecutan con EXEC, por ejemplo: EXEC dbo.SP_Consultar_NominaEmpleado @Empleado_ID = 3;

9. Funciones en SQL Server

Se recomienda usar funciones cuando se necesita una logica de calculo reutilizable y consistente, por ejemplo salario anual, impuestos o conversiones que se repiten en varias consultas.

10. Triggers

Automatizar con triggers ayuda a mantener auditoria, integridad, trazabilidad e historial sin depender de que el usuario recuerde ejecutar procesos manuales.

11. Vistas materializadas

Pregunta 1. Una vista normal es virtual; una vista materializada o indexada guarda estructura fisica para acelerar lecturas.

Pregunta 2. Se recomienda en consultas agregadas muy usadas, con gran volumen de lectura y cambios relativamente controlados.

12. Seguridad: usuarios, roles y permisos

Pregunta 1. El principio de minimo privilegio significa asignar solo los permisos estrictamente necesarios.

Pregunta 2. La seguridad en BD es importante para proteger confidencialidad, integridad, disponibilidad, auditoria y cumplimiento.
